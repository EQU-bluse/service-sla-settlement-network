# Service SLA Settlement Network

面向 API、Agent 与设备协作的后端服务基线。系统将机器服务协议、可验证遥测、结算与争议处理组织为可审计的 HTTP 能力。

## 环境

- Python 3.12+
- SQLite（Python 标准库）

## 启动

```bash
python3 -m sla_network --host 127.0.0.1 --port 8080 --database var/service-sla.db
```

启动命令另提供可选 `--arbitrator 机器标识`（`[0-9a-f]{64}`）配置终局仲裁机器；标识格式非法时进程以退出码 `2` 拒绝启动，省略时其余行为与此前一致。

服务启动后提供：

- `GET /health`：返回 JSON 健康状态，成功响应为 `200`。
- `POST /v1/machines`：登记机器身份。请求须携带 `Idempotency-Key` 头（`[A-Za-z0-9-]{1,64}`），JSON 请求体仅含 `publicKey`（`[0-9a-f]{64}`）。`id` 为 `SHA-256(bytes.fromhex(publicKey))` 的小写十六进制。首次登记返回 `201`；同键同 `publicKey` 重放返回 `200`；同键异 `publicKey` 返回 `409`/`idempotency_conflict`；异键同 `id` 返回 `409`/`machine_exists`。登记同时建立该机器的密钥版本一历史（`version=1`、激活时刻为零、未吊销），登记与幂等记录在同一原子提交中持久化，重启后重放语义不变。
- `POST /v1/machines/{id}/keys`：轮换机器密钥。请求须携带 `Idempotency-Key` 头（格式同上）且不接受任何查询参数，JSON 请求体恰含且不得重复 `expectedVersion`（非布尔整数 `1..2147483646`）、`publicKey`（`[0-9a-f]{64}`）、`currentSignature`、`newSignature`（均为恰 128 位小写十六进制字符）。被签消息为 UTF-8 字符串 `key-rotate-v1\n机器id\nexpectedVersion\n新publicKey`（整数为无前导零十进制，各项逐行连接且末尾无换行）；`currentSignature` 以当前最新版本密钥验证、`newSignature` 以新公钥验证，均按 RFC 8032 严格 Ed25519 边界。判定顺序为头、查询参数与体、幂等记录、机器、版本、历史公钥复用、验签：头、查询参数或体非法返回 `400`/`invalid_request`；同键异 `id` 或异体返回 `409`/`conflict`（即使 `id` 未登记）；机器不存在返回 `404`/`not_found`；`expectedVersion` 不等于当前最新版本返回 `409`/`conflict`；新公钥等于该机器任一历史版本公钥返回 `409`/`key_exists`；任一签名验证失败返回 `409`/`invalid_signature`。首次成功原子写入下一版本（版本号为期望版本加一），激活时刻取事务 UTC 毫秒，返回 `201`，正文键序为 `version,publicKey,activatedAt,revoked`，`revoked` 为 `false`。同键同请求并发或重启后重放首次状态码与响应字节；轮换与幂等结果原子持久化，失败无写入；异键同版本（含并发与重启后重放）仅一项成功。
- `POST /v1/machines/{id}/keys/{version}/revocation`：吊销机器的一个历史密钥版本。请求须携带 `Idempotency-Key` 头（格式同上）且不接受任何查询参数，JSON 请求体仅含且不得重复 `signature`（恰 128 位小写十六进制字符）；路径 `version` 为无前导零十进制正整数。被签消息为 UTF-8 字符串 `key-revoke-v1\n机器id\nversion`（逐行连接、末尾无换行），由该机器最新版本密钥按严格 Ed25519 签署。判定顺序为头、查询参数与体、幂等记录、机器与版本、当前版、重复吊销、验签：头、查询参数或体非法返回 `400`/`invalid_request`；同键异 `id`、异版本或异体返回 `409`/`conflict`；机器或版本不存在（含版本号非法）返回 `404`/`not_found`；吊销当前最新版本返回 `409`/`conflict`；版本已吊销返回 `409`/`already_revoked`；验签失败（含查不到最新公钥）返回 `409`/`invalid_signature`。成功在同一写事务内原子置吊销标记并持久化幂等结果，返回 `200`，正文仅 `{"version":版本,"revoked":true}`。同键同请求并发或重启后重放首次状态码与响应字节；失败无写入。
- `POST /v1/machines/{id}/capabilities`：为已登记机器声明能力。请求须携带 `Idempotency-Key` 头（格式同上）与单一 `SLA-Auth` 头（见“请求认证”，机器标识须等于路径机器；也可改用单一 `SLA-Delegation` 头，见“代理认证”，两者并存返回 `400`/`invalid_request`），JSON 请求体恰含 `expectedVersion`（非布尔整数 `0..2147483646`）、`name`（`[a-z0-9-]{1,32}`）、`protocol`（`http|mqtt`）、`region`（`cn|eu|us`）、`unit`（`call|byte|ms`）、`capacity`（非布尔整数 `1..2147483647`），键不得重复或缺失。`protocol`、`region`、`unit` 必须为字符串（数组、对象等非字符串值返回 `400`，不断连）。首次声明仅接受 `expectedVersion: 0`，原子写入版本 `1` 并返回 `201`；更新须匹配当前版本，原子加一并返回 `200`。成功体仅 `{"version":新版本}`。判定顺序为头、体、幂等记录、机器、版本：头或体非法返回 `400`/`invalid_request`；同键异 `id` 或异字段返回 `409`/`conflict`（即使 `id` 未登记）；无幂等记录且机器不存在返回 `404`/`not_found`；版本不符返回 `409`/`conflict`。同键同请求重放（含并发与重启后）返回首次状态码与响应字节，仅写入一次；异键竞争同一机器版本仅一项成功。声明与幂等结果原子持久化，失败不留记录。认证失败码与认证相关判定次序另见“请求认证”，随机数与业务变更同事务原子提交。
- `POST /v1/sla-templates`：为机器当前能力版本创建 SLA 模板。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `id`（`[a-z0-9-]{1,64}`）、`machineId`（`[0-9a-f]{64}`）、`capabilityVersion`（非布尔整数 `1..2147483647`）、`priceMicros`（非布尔整数 `0..2147483647`）、`maxLatencyMs`（非布尔整数 `1..2147483647`）。机器须已登记，且其能力当前版本等于 `capabilityVersion`。首次创建原子返回 `201`，正文仅 `{"id":请求id}`。判定顺序为头、体、幂等记录、机器、能力版本、id：头或体非法返回 `400`/`invalid_request`；同键异请求返回 `409`/`conflict`；机器不存在返回 `404`/`not_found`；无能力或版本不符返回 `409`/`conflict`；id 已存在返回 `409`/`template_exists`。同键同请求并发或重启后重放首次响应字节与状态码；创建与幂等记录原子持久化，失败不留记录；异键同 id 并发仅一项成功。
- `POST /v1/slas`：基于 SLA 模板为消费者创建 SLA。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `id`（`[a-z0-9-]{1,64}`）、`templateId`（格式同 `id`）、`consumerId`（`[0-9a-f]{64}`）、`start`、`end`（均为非布尔整数 `0..2147483647`，UTC Unix 秒，且 `start < end`）。模板须存在、其机器当前能力版本等于模板绑定版本、消费者已登记；首次创建原子保存请求与模板快照，初态 `pending`，返回 `201`，正文仅 `{"id":请求id}`。判定顺序为头、体、幂等记录、模板、能力版本、消费者、id：头或体非法返回 `400`/`invalid_request`；同键异请求、模板缺失或版本失效返回 `409`/`conflict`；消费者缺失返回 `404`/`not_found`；异键同 id 返回 `409`/`sla_exists`。同键同请求并发或重启后重放首次响应字节与状态码；创建与幂等记录原子持久化，失败不留记录；异键同 id 并发仅一项成功。
- `POST /v1/slas/{id}/confirmations`：生产方或消费方确认 SLA。请求须携带 `Idempotency-Key` 头（格式同上）与单一 `SLA-Auth` 头（见“请求认证”，机器标识须等于正文 `actorId`），JSON 请求体仅含且不得重复 `party`（`producer|consumer`）、`actorId`（`[0-9a-f]{64}`）；`producer` 的 `actorId` 须等于快照中的 `machineId`，`consumer` 的 `actorId` 须等于快照中的 `consumerId`。事务取 UTC Unix 整秒 `now`，仅当 `start<=now<end` 且生产者能力当前版本等于快照版本时接受。每方限一次：首方确认后仍为 `pending`，第二方确认原子转为 `active`。成功返回 `200`，正文仅 `{"state":"pending"}` 或 `{"state":"active"}`。判定顺序为幂等头、体、幂等记录、SLA、参与方、重复方、时间/版本：头或体非法返回 `400`/`invalid_request`；同键异 id 或异体返回 `409`/`conflict`；SLA 不存在返回 `404`/`not_found`；`party` 与 `actorId` 不符返回 `403`/`forbidden`；异键同方重复确认返回 `409`/`already_confirmed`；时间窗外或版本不符返回 `409`/`conflict`。同键同请求并发或重启后重放首次状态码与响应字节；确认、幂等记录与状态变更在同一事务中持久化，失败不留任何记录或确认；异键并发每方至多成功一次且 `active` 仅转换一次。
- `GET /v1/slas/{id}`：返回 `200`，正文键序为 `id,templateId,machineId,consumerId,capabilityVersion,priceMicros,maxLatencyMs,start,end,state`，同名值取创建时请求或模板快照，`state` 为 `pending` 或双方确认后的 `active`。无记录（含非法 id）返回 `404`/`not_found`。
- `POST /v1/slas/{id}/telemetry`：为 active 状态的 SLA 写入一条遥测事件。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `eventId`（`[a-z0-9-]{1,64}`）、`timestamp`（非布尔整数 `0..2147483647999`，UTC Unix 毫秒）、`latencyMs`（非布尔整数 `0..2147483647`）、`digest`（`[0-9a-f]{64}`）、`keyVersion`（非布尔正整数）与 `signature`（恰 128 位小写十六进制字符）。`digest` 等于 UTF-8 字符串 `id\neventId\ntimestamp\nlatencyMs\nmachineId` 的 SHA-256（整数为无前导零十进制，`machineId` 取 SLA 快照）。`signature` 按 RFC 8032 以 `keyVersion` 对应历史版本登记的 `publicKey` 验证 Ed25519（严格边界同证据证明入口）；被签消息为 UTF-8 字符串 `telemetry-v2\nid\neventId\ntimestamp\nlatencyMs\ndigest\nkeyVersion\nmachineId`（整数为无前导零十进制，各项以换行分隔且末尾无换行），签名覆盖全部业务字段。仅当 SLA 为 `active` 且 `start*1000<=timestamp<end*1000` 时接受；事件时刻还须位于该密钥版本的激活区间内（不早于其 `activatedAt`，且若存在下一版本则早于下一版本 `activatedAt`），且该版本未吊销。首次原子写入事件（含签名与密钥版本）及幂等结果，返回 `201`，正文仅 `{"eventId":请求值}`。判定顺序为头、体、幂等记录、SLA、状态/时间、摘要、密钥版本窗口与签名、eventId：头或体非法（含缺少 `keyVersion`）返回 `400`/`invalid_request`；同键异 id 或异体返回 `409`/`conflict`；SLA 不存在返回 `404`/`not_found`；非 active、时间越界或摘要错误返回 `409`/`conflict`（不进入验签）；密钥版本未知、事件时刻不在该版本激活区间、版本已吊销或验签失败（含查不到登记公钥）返回 `409`/`invalid_signature`；异键重复 eventId 返回 `409`/`event_exists`。同键同请求并发或重启后重放首次状态码与响应字节；事件、签名与幂等结果原子持久化，失败不留记录、不写幂等结果也不推进提交序号；异键同 eventId 并发仅一项成功。全库共享一条持久化提交序号 `commit_seq`：空库首条事件为 `1`；首次成功的提交取提交前全库最大序号加一且全库唯一，失败请求或同键重放均不推进序号。事件、幂等结果与序号在同一事务中原子提交，跨 SLA 并发提交不得产生重复序号。旧库迁移时，在单事务内按 `sla_telemetry_events.rowid` 升序将既有事件稠密重编号为 `1..N` 并写入一次性标记；事件内容与幂等记录保持不变，重启后不再重编号。升级前事件（含无签名事件与 telemetry-v1 签名事件）不回填密钥版本、不补造签名、不重排序号，继续参与查询、评估与结算；旧幂等键与原请求正文精确匹配时仍重放原响应，其他旧正文提交按非法正文处理。升级与新登记均为每台机器建立版本一、零时激活且未吊销的密钥历史。
- `POST /v1/slas/{id}/evaluations`：对 active 状态的 SLA 在给定区间上做一次结算评估。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体恰含且不得重复 `from`、`to`，均为非布尔整数。仅当 SLA 为 `active` 且 `start*1000<=from<to<=end*1000` 时接受。事务起点取全库最大 `commit_seq` 为 `cut`（空库为 `0`），只聚合该 SLA 内 `commit_seq<=cut` 且 `timestamp∈[from,to)` 的事件；`count`、`latencySum`、`maxLatency`、`violations` 定义与遥测查询的 `summary` 相同（`violations` 为延迟严格大于 SLA 快照 `maxLatencyMs` 的事件数）。`outcome` 在 `count=0` 时为 `insufficient`，否则 `violations=0` 时为 `fulfilled`，其余为 `breached`。首次成功在同一写事务内原子分配全库共享的持久化评估序号 `evaluationSeq`（取全库最大序号加一，空库为 `1`，跨 SLA 唯一）与事务 UTC 毫秒时间 `createdAt`，二者均为非负整数；失败请求与同键重放均不分配序号。首次返回 `201`，正文键序为 `evaluationSeq,from,to,cut,count,latencySum,maxLatency,violations,outcome,createdAt`；`outcome` 为字符串，`maxLatency` 空时为 `null`，其余字段为非负整数。判定顺序为头、体、幂等记录、SLA、状态/区间：头或体非法返回 `400`/`invalid_request`；同键异 id 或异体返回 `409`/`conflict`；SLA 不存在返回 `404`/`not_found`；非 active 或区间越界（含 `from>=to`）返回 `409`/`conflict`。快照（`response_json` 字节）、序号、时间与幂等结果在同一事务原子持久化，后续遥测不得改变；同键同请求并发或重启后均重放首次状态码与响应字节（旧记录重放字节不含新增字段），失败不留记录。旧库迁移时，在单事务内按 `sla_evaluation_idempotency_records.rowid` 升序将既有记录稠密赋序号 `1..N`、`createdAt=0` 并写入一次性标记；不改动既有快照、幂等数据与重放字节，重启后不再重编号、不重排，跨 SLA 并发不重号。
- `GET /v1/slas/{id}/evaluations`：分页读取 SLA 结算评估。查询参数仅允许且每项限单值 `limit`、`cursor`；`limit` 为无前导零十进制整数、范围 `1..100`，缺省 `50`；`cursor=cut:lastSeq`，两段均为无前导零十进制整数。缺项、未知/重复参数、格式或范围非法均在 SLA 查询之前返回 `400`/`invalid_request`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大 `evaluationSeq`（空库为 `0`）；按序号升序返回该 SLA 内 `0<evaluationSeq<=cut` 的评估。续页在同一 `cut` 下再限 `evaluationSeq>lastSeq`。`cut` 大于当前全库最大序号、或 `lastSeq` 锚点在该 SLA 内且不大于 `cut` 却不存在，均为 `400`/`invalid_request`（这些状态校验在 SLA 查询之后）；SLA 不存在（含非法 id）为 `404`/`not_found`。成功为 `200`，正文键序 `evaluations,nextCursor`；`evaluations` 为对象数组，元素键序 `evaluationSeq,from,to,cut,count,latencySum,maxLatency,violations,outcome,createdAt`，字段类型与取值沿 POST（旧库迁移记录的 `createdAt` 为 `0`，其余取自快照）。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定；读取期间的并发新增不影响续页（全新首页才取新 `cut`）。
- `GET /v1/slas/{id}/telemetry`：分页读取 SLA 遥测事件。查询参数仅允许且每项限单值 `from`、`to`、`limit`、`cursor`；`from`、`to` 必填，为无前导零十进制整数且 `0<=from<to<=2147483648000`；`limit` 缺省 `50`、范围 `1..100`。缺项、未知/重复参数、格式或范围非法均为 `400`/`invalid_request`；SLA 不存在（含非法 id）为 `404`/`not_found`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大 `commit_seq`（空库为 `0`）；`events` 与 `summary` 仍只含目标 SLA 内序号不大于 `cut` 且 `timestamp∈[from,to)` 的事件，按 `timestamp,eventId` 升序。其他 SLA 的提交仅推进后续全新首页的 `cut`，不影响当前读取。`cursor=cut:lastTimestamp:lastEventId`（数字无前导零）：锚点须是目标 SLA 内序号不大于 `cut`、且位于当前 `[from,to)` 区间的对应事件，续页从其后开始；`cut` 大于当前全库最大序号、锚点事件不存在或不匹配均为 `400`/`invalid_request`。成功为 `200`，正文键序 `events,summary,nextCursor`：`events` 为对象数组，元素键序 `eventId,timestamp,latencyMs,digest`；`summary` 键序 `count,latencySum,maxLatency,violations`，依次为整个 `cut` 区间（非仅当前页）的事件数、延迟和、最大延迟（空为 `null`）、延迟严格大于 SLA 快照 `maxLatencyMs` 的事件数，非 null 值均为非负整数。有后页时 `nextCursor` 取本页末事件游标，否则为 `null`。`cut` 由游标携带并跨重启稳定；读取期间的并发新增不影响续页与汇总（全新首页才取新 `cut`）。

- `GET /v1/disputes`：按参与账户分页审计争议集合。查询参数仅允许且每项限单值 `accountId`、`state`、`limit`、`cursor`；`accountId` 必填且为 `[0-9a-f]{64}` 格式的已登记机器 id（不含 `external:clearing`），匹配争议的付款方或收款方；`state` 可省略，提供时仅接受 `open`、`released`、`refunded` 或 `escalated`，按快照状态收窄结果；`limit` 为无前导零十进制整数、范围 `1..100`，缺省 `50`；`cursor=cut:lastOpenedSeq`，两段均为无前导零十进制整数。缺少 `accountId`、未知/重复参数、格式或范围非法均在账户查询之前返回 `400`/`invalid_request`；格式合法但未登记的机器返回 `404`/`not_found`；合法账户未参与任何争议时返回 `200` 空页。无 `cursor` 时，`cut` 取同一读事务起点的全库最大争议事件序号（空库为 `0`）；按 `opened` 事件序号升序返回该账户参与且打开序号不大于 `cut` 的争议，每条争议的状态由 `cut` 以内最后一项生命周期事件推导（`opened` 即 `open`），不取当前状态。续页在同一 `cut` 下只读取锚点打开序号之后仍满足原账户与状态筛选的争议；`cut` 大于当前全库最大序号、或锚点不属于当前快照及筛选结果，均为 `400`/`invalid_request`（这些状态校验在账户查询之后）。成功为 `200`，正文键序 `disputes,nextCursor`；`disputes` 为对象数组，元素先沿用单笔争议详情的键序 `id,state,amount,claimantId,payerId,payeeId,settlementSeq,slaId,evaluationSeq,result`，项尾追加 `openedEventSeq,openedAt,resolvedEventSeq,resolvedAt`：`openedEventSeq` 为正整数打开事件序号，`openedAt` 为非负毫秒时间；快照仍为 `open` 时 `resolvedEventSeq` 与 `resolvedAt` 均为 `null`，否则为 `cut` 以内结果事件的序号与时间，类型同前。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末项打开序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定；新增争议及裁决产生的新事件不进入旧快照，读取期间的并发写入不影响续页（全新首页才取新 `cut`）；迁移补出的生命周期事件按原序号直接参与排序与状态推导，不重新编号。
- `POST /v1/evidence-proofs`：为一条已提交的不可变证据追加签名证明。请求须携带 `Idempotency-Key` 头（格式同上）、单一 `SLA-Auth` 头（见“请求认证”，机器标识须等于正文 `actorId`；也可改用单一 `SLA-Delegation` 头，见“代理认证”，两者并存返回 `400`/`invalid_request`）且不接受任何查询参数，JSON 请求体仅含且不得重复 `evidenceSeq`（非布尔正整数）、`actorId`（`[0-9a-f]{64}`）、`signature`（恰 128 位小写十六进制字符）。直接认证与代理认证的行为除认证本身外完全一致。两种认证头并存、缺失、重复或结构非法均返回 `400`/`invalid_request`，且先于查证据。签名按 RFC 8032 以 `actorId` 登记的 `publicKey` 验证 Ed25519；被签消息为 UTF-8 字符串 `proof-v1\n争议id\nevidenceSeq\n证据digest\nactorId`（整数为无前导零十进制，争议 id 与 digest 取该证据记录）的字节，业务签名始终由正文身份密钥覆盖，代理只负责传输。判定顺序为头、查询参数、体、幂等记录、证据、签名者身份（代理凭证还须范围匹配）、争议状态、验签、重复证明：头、查询参数或体非法返回 `400`/`invalid_request`，且先于一切资源查询；同键改换正文或认证五段返回 `409`/`conflict`，原请求则重放首次响应字节，且均先于资源查询；证据不存在返回 `404`/`not_found`；`actorId` 非该证据所属争议的付款方或收款方、代理凭证范围不符（操作非 `evidence.proof.write`、凭证 `evidenceSeq` 与正文证据不一致或签发身份越界）返回 `403`/`forbidden`；代理请求过时返回 `401`/`stale_request`，且不消费凭证、随机数或序号；委托未知、已过期、已使用、已撤销、签发密钥版本不再有效或代理验签失败返回 `401`/`invalid_authentication`，凭证失败后仍可重试；有效随机数异键复用返回 `409`/`replay_detected`，且不留幂等或消费记录；争议已裁决返回 `409`/`already_resolved`；验签失败（含查不到登记公钥）返回 `409`/`invalid_signature`；同一证据同一签名者已被异键证明返回 `409`/`proof_exists`（每条证据双方各可证明一次，唯一性在业务验签后最后判定）。首次成功在同一写事务内原子分配全库唯一、持久递增的证明序号 `proofSeq`（取全库最大序号加一，空库为 `1`，跨证据唯一）与非负事务 UTC 毫秒时间 `createdAt`，返回 `201`，正文键序为 `proofSeq,verified,createdAt`，`verified` 为 `true`。证明、`proofSeq`、`createdAt` 与幂等结果同事务原子持久化；使用代理凭证时还在同一事务写入委托消费标记并追加一条 `consumed` 生命周期事件（该事件记录被签名请求的标准路径 `/v1/evidence-proofs` 与服务收到的原始正文 SHA-256 小写摘要）；任何失败均不写记录、不消费凭证或随机数、不推进序号；同键同请求并发或重启后重放首次状态码与响应字节；同一签名者或同一凭证的异键并发至多成功一次。

- `GET /v1/machines/{id}/delegations`：按签发机器分页读取其委托。请求无正文，须携带恰好一个 `SLA-Auth` 头（见“请求认证”，机器标识须等于路径机器；正文摘要按空字节 SHA-256 计算）。查询参数仅允许且每项限单值 `limit`、`cursor`，格式、缺省值（`limit` 缺省 `50`、范围 `1..100`）与 `cursor=cut:lastSeq` 均沿用 SLA 评估历史查询。判定依次经过查询参数、认证结构、资源（路径机器）、签发身份、认证有效性、随机数、游标关联：查询参数缺失、重复、未知或格式非法返回 `400`/`invalid_request`；认证头缺失、重复或格式非法返回 `400`/`invalid_request`，均先于资源查询；路径机器不存在返回 `404`/`not_found`；认证机器与路径机器不一致返回 `403`/`forbidden`；认证机器未登记、时间、密钥或签名错误沿用“请求认证”的 `401` 状态码与次序；随机数复用返回 `409`/`replay_detected`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大委托事件序号（空库为 `0`）；委托按其 `issued` 事件序号升序返回 `0<issuedSeq<=cut` 的项，续页在同一 `cut` 下再限 `issuedSeq>lastSeq`。`cut` 大于当前全库最大事件序号、或 `lastSeq` 锚点不是该机器在 `cut` 内的签发事件（含属于其他机器、非签发事件或不存在）均为 `400`/`invalid_request`（游标校验在资源、身份与认证之后）。成功为 `200`，正文键序 `delegations,nextCursor`；`delegations` 为对象数组，元素前六键序为 `id,delegatePublicKey,expiresAt,issuedKeyVersion,consumed,revoked`，项尾追加 `operation,capabilityVersion,disputeId,evidenceSeq`：前四项取自委托记录，`consumed`、`revoked` 为该委托在 `cut` 以内是否已出现对应事件的布尔值（不读当前标记，后续消费/撤销不改变旧快照项），`operation`、`capabilityVersion`、`disputeId`、`evidenceSeq` 为凭证最小权限范围：能力授权取 `operation="capability.write"` 与对应 `capabilityVersion`、`disputeId` 与 `evidenceSeq` 为 `null`，单笔争议授权取 `operation="evidence.write"` 与对应 `disputeId`、`capabilityVersion` 与 `evidenceSeq` 为 `null`，证明授权取 `operation="evidence.proof.write"` 与对应 `evidenceSeq`、`capabilityVersion` 与 `disputeId` 为 `null`，升级前凭证四项均为 `null`。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末项签发事件序号`，否则为 `null`。仅成功读取才在同一事务消费随机数，任何失败均不消费；`cut` 由游标携带并跨重启稳定，读取期间并发签发、消费与撤销不影响续页（全新首页才取新 `cut`）。
- `GET /v1/delegations/{id}/events`：分页读取单张凭证的生命周期事件。请求无正文，须携带恰好一个 `SLA-Auth` 头（机器标识须等于该凭证的签发机器；正文摘要按空字节 SHA-256 计算）。查询参数、错误码与判定次序同上：参数或认证结构非法为 `400`/`invalid_request`（先于资源查询），委托不存在返回 `404`/`not_found`，认证机器不属签发者返回 `403`/`forbidden`，认证错误沿用“请求认证”的 `401` 状态码与次序，随机数复用为 `409`/`replay_detected`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大委托事件序号（空库为 `0`）；按事件序号升序返回该凭证 `0<eventSeq<=cut` 的 `issued`、`consumed`、`revoked` 事件，续页在同一 `cut` 下再限 `eventSeq>lastSeq`。`cut` 大于当前全库最大事件序号、或 `lastSeq` 锚点不属于目标凭证（含属于其他凭证或不存在）均为 `400`/`invalid_request`。成功为 `200`，正文键序 `events,nextCursor`；`events` 为对象数组，元素键序 `eventSeq,type,createdAt`，`eventSeq` 为全库唯一、持久递增的正整数，`type` 为 `issued`、`consumed` 或 `revoked`，`createdAt` 为事务 UTC 毫秒非负整数。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末事件序号`，否则为 `null`。仅成功读取才在同一事务消费随机数，任何失败均不消费；旧游标隔离并发签发、消费与撤销，服务重启后续页稳定。
- `GET /v1/machines/{id}/delegation-consumptions`：供签发机器分页读取成功消费记录。请求无正文，须携带恰好一个 `SLA-Auth` 头（机器标识须等于路径机器；正文摘要按空字节 SHA-256 计算）。查询参数仅允许且每项限单值 `limit`、`cursor`，格式、缺省值（`limit` 缺省 `50`、范围 `1..100`）与 `cursor=cut:lastSeq` 均沿用委托集合查询。判定依次经过查询参数、认证结构、资源（路径机器）、签发身份、认证有效性、随机数、游标关联：查询参数缺失、重复、未知或格式非法返回 `400`/`invalid_request`；认证头缺失、重复或格式非法返回 `400`/`invalid_request`，均先于资源查询；路径机器不存在返回 `404`/`not_found`；认证机器与路径机器不一致返回 `403`/`forbidden`；认证机器未登记、时间、密钥或签名错误沿用“请求认证”的 `401` 状态码与次序；随机数复用返回 `409`/`replay_detected`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大委托事件序号（空库为 `0`）；只按事件序号升序返回该机器所签发凭证在 `0<eventSeq<=cut` 内的 `consumed` 事件，续页在同一 `cut` 下再限 `eventSeq>lastSeq`。`cut` 大于当前全库最大事件序号、或 `lastSeq` 锚点不属于该机器当前 `cut` 内的消费结果（含属于其他机器、非 `consumed` 事件或不存在）均为 `400`/`invalid_request`（游标校验在资源、身份与认证之后）。成功为 `200`，正文键序 `consumptions,nextCursor`；`consumptions` 为对象数组，元素键序 `eventSeq,delegationId,operation,capabilityVersion,resource,requestDigest,createdAt,evidenceSeq`：`eventSeq` 为全库唯一、持久递增的正整数，`delegationId` 为被消费凭证 id，`operation`、`capabilityVersion` 与 `evidenceSeq` 取自凭证最小权限范围（升级前凭证均为 `null`），`resource` 为首次成功消费时被签名请求的标准路径，`requestDigest` 为该请求服务收到的原始正文之 SHA-256 小写十六进制，`createdAt` 为事务 UTC 毫秒非负整数。升级前的旧 `consumed` 事件保留原事件序号，`operation`、`capabilityVersion`、`resource`、`requestDigest`、`evidenceSeq` 均为 `null`，`createdAt` 沿用旧事件时间（迁移补出者为 `0`）。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末消费事件序号`，否则为 `null`。仅成功读取才在同一事务消费随机数，任何失败均不消费；`cut` 由游标携带并跨重启稳定，旧游标隔离并发且跨重启稳定，读取期间并发签发、消费与撤销不影响续页（全新首页才取新 `cut`）。

委托事件迁移：旧库升级时在单事务内按 `machine_delegations.rowid` 升序为每张既有委托补一条 `issued`，再依现有标记紧随补 `consumed`、`revoked`（先消费后撤销），事件序号在全库内稠密递增、时间一律记零；不改动旧委托、幂等记录与响应字节，迁移仅执行一次，重启后不再补写。

最小权限与消费审计迁移：旧库升级时在单事务内为 `machine_delegations` 补可空列 `operation`、`capability_version`，为 `delegation_events` 补可空列 `resource`、`request_digest`；既有委托与既有 `consumed` 事件的新列一律保持 `NULL`（旧凭证按无范围语义消费，旧消费事件新增业务元数据均为 null），不改动旧序号、旧幂等记录与重放字节。升级前的三字段签发幂等记录在同键同原正文（逐字节）重放时继续返回首次响应，不补范围字段；迁移仅执行一次，重启后不再补写。

单笔争议证据授权迁移：旧库升级时在单事务内为 `machine_delegations` 补可空列 `dispute_id`，既有委托（含能力授权与升级前无范围凭证）一律保持 `NULL`；不改旧凭证、事件序号、幂等数据或历史响应字节。委托集合在既有字段末尾追加 `disputeId`：能力授权及升级前凭证为 `null`，证据授权记录其争议标识。升级前无范围凭证仍只能按原来的能力声明语义消费，不获得证据权限。迁移仅执行一次，重启后不再补写。

单条证据证明授权迁移：旧库升级时在单事务内为 `machine_delegations` 补可空列 `evidence_seq`，既有委托（含能力授权、单笔争议授权与升级前无范围凭证）一律保持 `NULL`；不改旧凭证、事件序号、幂等数据或历史响应字节。委托集合在既有字段末尾追加 `evidenceSeq`，消费审计同样在项尾追加 `evidenceSeq`：证明授权记录其证据序号，其余委托与升级前凭证、旧消费事件均为 `null`。升级前凭证不获得证明权限。迁移仅执行一次，重启后不再补写。

分歧超时升级迁移：旧库升级时仅新增升级存储（`dispute_escalations` 与 `dispute_escalation_idempotency_records`）与序号状态，不改动既有争议、提案、账本、事件、幂等数据与历史响应字节；既有争议无升级记录，升级序号自 `1` 起全库递增。

终局仲裁迁移：旧库升级时仅新增仲裁存储（`dispute_arbitrations` 与 `dispute_arbitration_idempotency_records`）与序号状态，不改动既有争议、升级、账本、事件、幂等数据与历史响应字节；既有 `escalated` 争议可直接仲裁，仲裁序号自 `1` 起全库递增。

## 请求认证（SLA-Auth）

能力声明、SLA 确认、争议证据、证据证明、证据快照创建、双边裁决提案提交、分歧超时升级、终局仲裁、委托签发与委托撤销等写入口，以及委托集合、委托事件、委托消费记录与证据快照集合、单笔快照、裁决提案集合、升级记录集合、仲裁记录集合八个审计读取入口，统一要求请求认证（签名与防重放）。

- 首次请求须携带恰好一个 `SLA-Auth` 请求头，其值为五段 ASCII 文本以分号 `;` 连接：`机器标识;密钥版本;请求时间;随机数;签名`。
  - 机器标识为 `[0-9a-f]{64}`，与 `sha256(publicKey)` 形式一致；
  - 密钥版本为无前导零正整数，对应该机器当前最新（未吊销）密钥版本；
  - 请求时间为无前导零 UTC 毫秒；
  - 随机数匹配 `[A-Za-z0-9-]{16,64}`；
  - 签名为 128 位小写十六进制（64 字节 Ed25519 签名）。
- 待签字节为 UTF-8 字符串 `request-auth-v1\n大写方法\n标准路径\n正文摘要\n请求时间\n随机数\n密钥版本\n机器标识`，末尾不得出现换行。
  - 标准路径为请求目标问号前的 ASCII 路径（业务标识保持公开入口规定的形式，含百分号编码原样）；
  - 正文摘要为服务收到的原始正文之 SHA-256 小写十六进制，不重新序列化 JSON；
  - 签名按 RFC 8032 以机器标识对应机器的指定版本登记公钥做严格 Ed25519 验证。
- 机器标识必须等于能力路径机器、确认/证据/证明/快照/提案正文 `actorId`（其中确认按参与方解析为 SLA 快照 `machineId` 或 `consumerId`）；终局仲裁入口的机器标识须等于启动时配置的仲裁机器，不一致返回 `403`/`forbidden`。
- 请求时间与服务当前 UTC 毫秒相差超过 300000 返回 `401`/`stale_request`；密钥不存在、不是届时最新版本、已吊销或未通过严格验签，统一返回 `401`/`invalid_authentication`；认证头缺失、重复或格式非法返回 `400`/`invalid_request`，且先于一切资源与业务检查（各入口既有的幂等头、查询参数与正文非法判定仍按各端点说明的次序执行）。
- 认证结构通过后先处理既有幂等记录：同键同请求直接重放首次响应且不再次消费随机数；未命中幂等记录后，依次检查资源和签名者、时间、密钥与签名、随机数，再执行既有业务判定。
- 同键更换认证五段或业务请求仍返回 `409`/`conflict`；同一机器以异键复用有效期内随机数返回 `409`/`replay_detected`。只有首次业务成功才在同一事务原子写入随机数、业务变更与幂等结果；任何失败均不消费随机数、不推进任何全局序号。随机数记录至少保留到请求时间后十分钟，此后可清理；过期请求仍由时间窗口拒绝。
- 升级前已有的幂等记录是唯一例外：按原请求先行重放，不补认证数据、不校验认证头；升级后新建的幂等记录在重放时认证五段必须与首次完全一致。

## 代理认证（SLA-Delegation）

能力声明、争议证据提交与证据证明入口可用恰好一个 `SLA-Delegation` 请求头替代 `SLA-Auth`；两者并存返回 `400`/`invalid_request`。

- 头值复用 SLA-Auth 五段格式：`委托id;0;请求时间;随机数;签名`。首段为签发时的委托 `id`（`[a-z0-9-]{1,64}`），版本段固定为 `0`，请求时间、随机数与签名的格式同 SLA-Auth；头缺失、重复、段数或各段格式非法（含版本段非 `0`）返回 `400`/`invalid_request`，且先于一切资源与业务检查（旧幂等记录重放例外同 SLA-Auth）。
- 待签字节为 UTF-8 字符串 `delegation-auth-v1\n大写方法\n标准路径\n正文摘要\n请求时间\n随机数\n0\n委托id`，末尾不得出现换行；标准路径与正文摘要的定义同 SLA-Auth；签名按 RFC 8032 以签发时登记的 `delegatePublicKey` 做严格 Ed25519 验证。
- 路径资源必须属于签发机器：能力声明入口要求路径机器等于签发机器；争议证据与证据证明入口要求正文 `actorId` 等于签发机器且其为该争议付款方或收款方，不一致返回 `403`/`forbidden`。凭证最小权限范围还须与本次请求一致：能力声明入口的操作为 `capability.write`，且正文 `expectedVersion` 须等于凭证 `capabilityVersion`；争议证据入口的操作为 `evidence.write`，且路径争议 `disputeId` 须等于凭证 `disputeId`；证据证明入口的操作为 `evidence.proof.write`，且正文 `evidenceSeq` 须等于凭证 `evidenceSeq`（均不校验正文其他字段）。任一不符返回 `403`/`forbidden`，且不消费凭证、随机数或事件序号。升级前凭证的范围为 null，仍只按能力声明入口原有的无范围语义消费，不获得证据或证明权限：在证据与证明入口一律返回 `403`/`forbidden`。请求时间与服务当前 UTC 毫秒相差超过 300000 返回 `401`/`stale_request`；委托未知、已过期、已使用、已撤销或签发密钥版本不再有效（不是签发机器当前最新且未吊销的版本）统一返回 `401`/`invalid_authentication`。范围校验先于时间窗与凭证状态判定。
- 随机数防重放与同键更换认证五段的错误语义沿用 SLA-Auth。仅首次业务成功（能力声明成功、首次证据成功或首次证明成功）才在同一事务原子写入随机数、委托消费标记、`consumed` 生命周期事件、业务变更与幂等结果；该 `consumed` 事件同时保存被签名请求的标准路径（`resource`）与服务收到的原始正文 SHA-256 小写摘要（`requestDigest`）。异键并发使用同一委托至多一项成功；任何失败或同键重放均不消费凭证、不追加事件、不推进事件序号。能力声明、证据提交与证明提交各自原有的正文校验、竞争与响应不变。
