# Service SLA Settlement Network

面向 API、Agent 与设备协作的后端服务基线。系统将机器服务协议、可验证遥测、结算与争议处理组织为可审计的 HTTP 能力。

## 环境

- Python 3.12+
- SQLite（Python 标准库）

## 启动

```bash
python3 -m sla_network --host 127.0.0.1 --port 8080 --database var/service-sla.db
```

服务启动后提供：

- `GET /health`：返回 JSON 健康状态，成功响应为 `200`。
- `POST /v1/machines`：登记机器身份。请求须携带 `Idempotency-Key` 头（`[A-Za-z0-9-]{1,64}`），JSON 请求体仅含 `publicKey`（`[0-9a-f]{64}`）。`id` 为 `SHA-256(bytes.fromhex(publicKey))` 的小写十六进制。首次登记返回 `201`；同键同 `publicKey` 重放返回 `200`；同键异 `publicKey` 返回 `409`/`idempotency_conflict`；异键同 `id` 返回 `409`/`machine_exists`。登记与幂等记录在同一原子提交中持久化，重启后重放语义不变。
- `POST /v1/machines/{id}/capabilities`：为已登记机器声明能力。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体恰含 `expectedVersion`（非布尔整数 `0..2147483646`）、`name`（`[a-z0-9-]{1,32}`）、`protocol`（`http|mqtt`）、`region`（`cn|eu|us`）、`unit`（`call|byte|ms`）、`capacity`（非布尔整数 `1..2147483647`），键不得重复或缺失。`protocol`、`region`、`unit` 必须为字符串（数组、对象等非字符串值返回 `400`，不断连）。首次声明仅接受 `expectedVersion: 0`，原子写入版本 `1` 并返回 `201`；更新须匹配当前版本，原子加一并返回 `200`。成功体仅 `{"version":新版本}`。判定顺序为头、体、幂等记录、机器、版本：头或体非法返回 `400`/`invalid_request`；同键异 `id` 或异字段返回 `409`/`conflict`（即使 `id` 未登记）；无幂等记录且机器不存在返回 `404`/`not_found`；版本不符返回 `409`/`conflict`。同键同请求重放（含并发与重启后）返回首次状态码与响应字节，仅写入一次；异键竞争同一机器版本仅一项成功。声明与幂等结果原子持久化，失败不留记录。
- `POST /v1/sla-templates`：为机器当前能力版本创建 SLA 模板。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `id`（`[a-z0-9-]{1,64}`）、`machineId`（`[0-9a-f]{64}`）、`capabilityVersion`（非布尔整数 `1..2147483647`）、`priceMicros`（非布尔整数 `0..2147483647`）、`maxLatencyMs`（非布尔整数 `1..2147483647`）。机器须已登记，且其能力当前版本等于 `capabilityVersion`。首次创建原子返回 `201`，正文仅 `{"id":请求id}`。判定顺序为头、体、幂等记录、机器、能力版本、id：头或体非法返回 `400`/`invalid_request`；同键异请求返回 `409`/`conflict`；机器不存在返回 `404`/`not_found`；无能力或版本不符返回 `409`/`conflict`；id 已存在返回 `409`/`template_exists`。同键同请求并发或重启后重放首次响应字节与状态码；创建与幂等记录原子持久化，失败不留记录；异键同 id 并发仅一项成功。
- `POST /v1/slas`：基于 SLA 模板为消费者创建 SLA。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `id`（`[a-z0-9-]{1,64}`）、`templateId`（格式同 `id`）、`consumerId`（`[0-9a-f]{64}`）、`start`、`end`（均为非布尔整数 `0..2147483647`，UTC Unix 秒，且 `start < end`）。模板须存在、其机器当前能力版本等于模板绑定版本、消费者已登记；首次创建原子保存请求与模板快照，初态 `pending`，返回 `201`，正文仅 `{"id":请求id}`。判定顺序为头、体、幂等记录、模板、能力版本、消费者、id：头或体非法返回 `400`/`invalid_request`；同键异请求、模板缺失或版本失效返回 `409`/`conflict`；消费者缺失返回 `404`/`not_found`；异键同 id 返回 `409`/`sla_exists`。同键同请求并发或重启后重放首次响应字节与状态码；创建与幂等记录原子持久化，失败不留记录；异键同 id 并发仅一项成功。
- `POST /v1/slas/{id}/confirmations`：生产方或消费方确认 SLA。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `party`（`producer|consumer`）、`actorId`（`[0-9a-f]{64}`）；`producer` 的 `actorId` 须等于快照中的 `machineId`，`consumer` 的 `actorId` 须等于快照中的 `consumerId`。事务取 UTC Unix 整秒 `now`，仅当 `start<=now<end` 且生产者能力当前版本等于快照版本时接受。每方限一次：首方确认后仍为 `pending`，第二方确认原子转为 `active`。成功返回 `200`，正文仅 `{"state":"pending"}` 或 `{"state":"active"}`。判定顺序为幂等头、体、幂等记录、SLA、参与方、重复方、时间/版本：头或体非法返回 `400`/`invalid_request`；同键异 id 或异体返回 `409`/`conflict`；SLA 不存在返回 `404`/`not_found`；`party` 与 `actorId` 不符返回 `403`/`forbidden`；异键同方重复确认返回 `409`/`already_confirmed`；时间窗外或版本不符返回 `409`/`conflict`。同键同请求并发或重启后重放首次状态码与响应字节；确认、幂等记录与状态变更在同一事务中持久化，失败不留任何记录或确认；异键并发每方至多成功一次且 `active` 仅转换一次。
- `GET /v1/slas/{id}`：返回 `200`，正文键序为 `id,templateId,machineId,consumerId,capabilityVersion,priceMicros,maxLatencyMs,start,end,state`，同名值取创建时请求或模板快照，`state` 为 `pending` 或双方确认后的 `active`。无记录（含非法 id）返回 `404`/`not_found`。
- `POST /v1/slas/{id}/telemetry`：为 active 状态的 SLA 写入一条遥测事件。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `eventId`（`[a-z0-9-]{1,64}`）、`timestamp`（非布尔整数 `0..2147483647999`，UTC Unix 毫秒）、`latencyMs`（非布尔整数 `0..2147483647`）、`digest`（`[0-9a-f]{64}`）。`digest` 等于 UTF-8 字符串 `id\neventId\ntimestamp\nlatencyMs\nmachineId` 的 SHA-256（整数为无前导零十进制，`machineId` 取 SLA 快照）。仅当 SLA 为 `active` 且 `start*1000<=timestamp<end*1000` 时接受。首次原子写入事件及幂等结果，返回 `201`，正文仅 `{"eventId":请求值}`。判定顺序为头、体、幂等记录、SLA、状态/时间、摘要、eventId：头或体非法返回 `400`/`invalid_request`；同键异 id 或异体返回 `409`/`conflict`；SLA 不存在返回 `404`/`not_found`；非 active、时间越界或摘要错误返回 `409`/`conflict`；异键重复 eventId 返回 `409`/`event_exists`。同键同请求并发或重启后重放首次状态码与响应字节；事件与幂等结果原子持久化，失败不留记录；异键同 eventId 并发仅一项成功。全库共享一条持久化提交序号 `commit_seq`：空库首条事件为 `1`；首次成功的提交取提交前全库最大序号加一且全库唯一，失败请求或同键重放均不推进序号。事件、幂等结果与序号在同一事务中原子提交，跨 SLA 并发提交不得产生重复序号。旧库迁移时，在单事务内按 `sla_telemetry_events.rowid` 升序将既有事件稠密重编号为 `1..N` 并写入一次性标记；事件内容与幂等记录保持不变，重启后不再重编号。
- `POST /v1/slas/{id}/evaluations`：对 active 状态的 SLA 在给定区间上做一次结算评估。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体恰含且不得重复 `from`、`to`，均为非布尔整数。仅当 SLA 为 `active` 且 `start*1000<=from<to<=end*1000` 时接受。事务起点取全库最大 `commit_seq` 为 `cut`（空库为 `0`），只聚合该 SLA 内 `commit_seq<=cut` 且 `timestamp∈[from,to)` 的事件；`count`、`latencySum`、`maxLatency`、`violations` 定义与遥测查询的 `summary` 相同（`violations` 为延迟严格大于 SLA 快照 `maxLatencyMs` 的事件数）。`outcome` 在 `count=0` 时为 `insufficient`，否则 `violations=0` 时为 `fulfilled`，其余为 `breached`。首次成功在同一写事务内原子分配全库共享的持久化评估序号 `evaluationSeq`（取全库最大序号加一，空库为 `1`，跨 SLA 唯一）与事务 UTC 毫秒时间 `createdAt`，二者均为非负整数；失败请求与同键重放均不分配序号。首次返回 `201`，正文键序为 `evaluationSeq,from,to,cut,count,latencySum,maxLatency,violations,outcome,createdAt`；`outcome` 为字符串，`maxLatency` 空时为 `null`，其余字段为非负整数。判定顺序为头、体、幂等记录、SLA、状态/区间：头或体非法返回 `400`/`invalid_request`；同键异 id 或异体返回 `409`/`conflict`；SLA 不存在返回 `404`/`not_found`；非 active 或区间越界（含 `from>=to`）返回 `409`/`conflict`。快照（`response_json` 字节）、序号、时间与幂等结果在同一事务原子持久化，后续遥测不得改变；同键同请求并发或重启后均重放首次状态码与响应字节（旧记录重放字节不含新增字段），失败不留记录。旧库迁移时，在单事务内按 `sla_evaluation_idempotency_records.rowid` 升序将既有记录稠密赋序号 `1..N`、`createdAt=0` 并写入一次性标记；不改动既有快照、幂等数据与重放字节，重启后不再重编号、不重排，跨 SLA 并发不重号。
- `GET /v1/slas/{id}/evaluations`：分页读取 SLA 结算评估。查询参数仅允许且每项限单值 `limit`、`cursor`；`limit` 为无前导零十进制整数、范围 `1..100`，缺省 `50`；`cursor=cut:lastSeq`，两段均为无前导零十进制整数。缺项、未知/重复参数、格式或范围非法均在 SLA 查询之前返回 `400`/`invalid_request`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大 `evaluationSeq`（空库为 `0`）；按序号升序返回该 SLA 内 `0<evaluationSeq<=cut` 的评估。续页在同一 `cut` 下再限 `evaluationSeq>lastSeq`。`cut` 大于当前全库最大序号、或 `lastSeq` 锚点在该 SLA 内且不大于 `cut` 却不存在，均为 `400`/`invalid_request`（这些状态校验在 SLA 查询之后）；SLA 不存在（含非法 id）为 `404`/`not_found`。成功为 `200`，正文键序 `evaluations,nextCursor`；`evaluations` 为对象数组，元素键序 `evaluationSeq,from,to,cut,count,latencySum,maxLatency,violations,outcome,createdAt`，字段类型与取值沿 POST（旧库迁移记录的 `createdAt` 为 `0`，其余取自快照）。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定；读取期间的并发新增不影响续页（全新首页才取新 `cut`）。
- `GET /v1/slas/{id}/telemetry`：分页读取 SLA 遥测事件。查询参数仅允许且每项限单值 `from`、`to`、`limit`、`cursor`；`from`、`to` 必填，为无前导零十进制整数且 `0<=from<to<=2147483648000`；`limit` 缺省 `50`、范围 `1..100`。缺项、未知/重复参数、格式或范围非法均为 `400`/`invalid_request`；SLA 不存在（含非法 id）为 `404`/`not_found`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大 `commit_seq`（空库为 `0`）；`events` 与 `summary` 仍只含目标 SLA 内序号不大于 `cut` 且 `timestamp∈[from,to)` 的事件，按 `timestamp,eventId` 升序。其他 SLA 的提交仅推进后续全新首页的 `cut`，不影响当前读取。`cursor=cut:lastTimestamp:lastEventId`（数字无前导零）：锚点须是目标 SLA 内序号不大于 `cut`、且位于当前 `[from,to)` 区间的对应事件，续页从其后开始；`cut` 大于当前全库最大序号、锚点事件不存在或不匹配均为 `400`/`invalid_request`。成功为 `200`，正文键序 `events,summary,nextCursor`：`events` 为对象数组，元素键序 `eventId,timestamp,latencyMs,digest`；`summary` 键序 `count,latencySum,maxLatency,violations`，依次为整个 `cut` 区间（非仅当前页）的事件数、延迟和、最大延迟（空为 `null`）、延迟严格大于 SLA 快照 `maxLatencyMs` 的事件数，非 null 值均为非负整数。有后页时 `nextCursor` 取本页末事件游标，否则为 `null`。`cut` 由游标携带并跨重启稳定；读取期间的并发新增不影响续页与汇总（全新首页才取新 `cut`）。
- `POST /v1/funds/{id}`：为已登记机器的零初始余额账户入金。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `amountMicros`（非布尔整数 `1..9000000000000000`）与 `reference`（`[a-z0-9-]{1,64}`）。判定顺序为头、体、幂等记录、机器：头或体非法返回 `400`/`invalid_request`；同键异 `id` 或异体返回 `409`/`conflict`（即使 `id` 未登记）；机器不存在返回 `404`/`not_found`。首次入金在同一写事务内原子分配全库共享的持久化入金序号 `depositSeq`（取全库最大序号加一，空库为 `1`，跨机器唯一），机器账户记入 `amountMicros`、外部清算账户记入等额反向分录，返回 `201`，正文键序 `depositSeq,balance`，`balance` 为入金后机器账户新余额。同键同请求并发或重启后重放首次状态码与响应字节；序号、双方分录、余额与幂等结果在同一事务原子提交，失败不留记录，跨机器并发不重号、不透支。
- `POST /v1/settlements`：将一次结算评估过账为资金结算。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `slaId`（`[a-z0-9-]{1,64}`）与 `evaluationSeq`（非布尔正整数）。判定顺序为头、体、幂等记录、SLA、评估归属、重复结算、金额、余额：头或体非法返回 `400`/`invalid_request`；同键异请求返回 `409`/`conflict`；SLA 或评估不存在返回 `404`/`not_found`；SLA 非 `active` 或评估不属于该 SLA 返回 `409`/`conflict`；评估已被异键结算返回 `409`/`settlement_exists`；金额或结算后余额超过 `9000000000000000` 返回 `409`/`amount_overflow`；付款方余额不足返回 `409`/`insufficient_funds`。评估为 `fulfilled` 时按快照单价乘事件数向消费者收费、转账给生产者（`charged`）；为 `breached` 时按快照单价乘违规数由生产者赔付消费者（`compensated`）；为 `insufficient` 时创建金额为零的 `pending` 结算，不产生账本分录。首次成功在同一写事务内原子分配全库共享的持久化结算序号 `settlementSeq`（取全库最大序号加一，空库为 `1`）与事务 UTC 毫秒时间 `createdAt`，双方分录、余额、结算记录与幂等结果同事务提交，失败无任何副作用。成功返回 `201`，正文键序 `settlementSeq,evaluationSeq,result,amount,createdAt`，`result` 为 `charged`、`compensated` 或 `pending`。同键同请求并发或重启后重放首次状态码与响应字节；每个评估至多结算一次，跨 SLA 并发不重号、不透支。
- `GET /v1/slas/{id}/settlements`：分页读取 SLA 资金结算。查询参数仅允许且每项限单值 `limit`、`cursor`；`limit` 为无前导零十进制整数、范围 `1..100`，缺省 `50`；`cursor=cut:lastSeq`，两段均为无前导零十进制整数。缺项、未知/重复参数、格式或范围非法均在 SLA 查询之前返回 `400`/`invalid_request`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大 `settlementSeq`（空库为 `0`）；按全局序号升序返回该 SLA 内 `0<settlementSeq<=cut` 的结算，续页在同一 `cut` 下再限 `settlementSeq>lastSeq`。`cut` 大于当前全库最大序号、或 `lastSeq` 锚点在该 SLA 内且不大于 `cut` 却不存在，均为 `400`/`invalid_request`（这些状态校验在 SLA 查询之后）；SLA 不存在（含非法 id）为 `404`/`not_found`。成功为 `200`，正文键序 `settlements,nextCursor`；`settlements` 为对象数组，元素键序 `settlementSeq,evaluationSeq,result,amount,payerId,payeeId,createdAt`，前四字段与时间沿用 POST 结算响应取值，`payerId`、`payeeId` 在 `pending` 时为 `null`，其余为机器 id。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定；读取期间的并发新增不影响续页（全新首页才取新 `cut`）；旧库结算按原序号直接参与分页。
- `GET /v1/accounts/{id}/ledger`：分页读取账户账本分录。账户仅接受已登记机器 id 或 `external:clearing`；合法账户无分录时返回空页，其他账户返回 `404`/`not_found`。查询参数、`limit`、`cursor=cut:lastSeq` 的格式与范围、缺项/未知/重复参数处理及错误次序均沿用 SLA 评估查询（参数错误先于账户查询返回 `400`/`invalid_request`）。无 `cursor` 时，`cut` 取同一读事务起点的全库最大 `entrySeq`（空库为 `0`）；按全局 `entrySeq` 升序返回目标账户内 `0<entrySeq<=cut` 的分录，续页在同一 `cut` 下再限 `entrySeq>lastSeq`。`cut` 大于当前全库最大序号、或 `lastSeq` 锚点在目标账户内且不大于 `cut` 却不存在，均为 `400`/`invalid_request`（这些状态校验在账户查询之后）。成功为 `200`，正文键序 `entries,nextCursor`；`entries` 为对象数组，元素键序固定为 `entrySeq,kind,referenceSeq,reference,slaId,evaluationSeq,delta,balanceAfter,createdAt`。`deposit` 分录 `reference` 为入金原始引用、`slaId` 与 `evaluationSeq` 为 `null`；`settlement` 分录反之，`reference` 为 `null`，`slaId`、`evaluationSeq` 关联对应结算的 SLA 与评估；`dispute_refund` 分录 `reference` 为 `null`，`referenceSeq` 为被退款结算的结算序号，`slaId`、`evaluationSeq` 关联该结算。`delta`、`balanceAfter` 为有符号整数，`createdAt` 为非负整数。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定，读取期间的并发新增不影响续页（全新首页才取新 `cut`）；旧库分录按原 `entrySeq` 直接参与分页。
- `POST /v1/disputes`：对一笔正金额结算创建争议并冻结收款方等额资金。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `id`（`[a-z0-9-]{1,64}`）、`settlementSeq`（非布尔正整数）、`claimantId`（`[0-9a-f]{64}`）。判定顺序为头、体、幂等记录、结算、身份、状态、唯一性：头或体非法返回 `400`/`invalid_request`；同键异请求返回 `409`/`conflict`；结算不存在返回 `404`/`not_found`；`claimantId` 非原付款方返回 `403`/`forbidden`；结算为 `pending`、零金额或其他不可争议状态返回 `409`/`conflict`；异键重复 `id` 或重复结算序号返回 `409`/`dispute_exists`。仅 `charged` 或 `compensated` 且金额为正的结算可被其原付款方争议。首次成功在同一写事务内原子冻结收款方等额资金（冻结仅登记 open 争议、不写账本）并记录一条 `opened` 生命周期事件，返回 `201`，正文键序 `id,open,amount`，`open` 为 `true`，`amount` 为结算金额。账户可用余额为总余额扣除全部 open 争议冻结额后与零的较大值（旧库冻结超额时按零判断）；入金先补缺口，结算扣款仅可使用可用余额。同键同请求并发或重启后重放首次状态码与响应字节；争议、生命周期事件与幂等结果原子持久化，失败无任何副作用也不写事件；并发创建同一争议至多成功一次。
- `POST /v1/disputes/{id}/resolution`：裁决一笔 open 争议。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `decision`（`release|refund`）。`release` 整笔解冻且不写账本；`refund` 将金额自收款方退回付款方，双方各写一笔 `dispute_refund` 分录，`referenceSeq` 为结算序号并保留 SLA 与评估关联；收款方总余额不足时返回 `409`/`insufficient_funds`，争议维持 `open` 且冻结不变，余额、账本、幂等结果与生命周期事件均不写入。判定顺序为头、体、幂等记录、争议、状态、余额：头或体非法返回 `400`/`invalid_request`；同键异请求返回 `409`/`conflict`；争议不存在返回 `404`/`not_found`；异键重复裁决返回 `409`/`already_resolved`。成功返回 `200`，正文键序 `id,released,amount` 或 `id,refunded,amount`，布尔字段为 `true`，`amount` 为争议金额。成功裁决在同一写事务内原子记录一条 `released` 或 `refunded` 生命周期事件；裁决、余额、分录、事件与幂等结果在同一事务原子持久化，任何失败均无任何副作用、不写事件；同键同请求并发或重启后重放首次状态码与响应字节，且事件不重复。
- `GET /v1/disputes/{id}`：读取争议当前状态。返回 `200`，正文键序为 `id,state,amount,claimantId,payerId,payeeId,settlementSeq,slaId,evaluationSeq,result`；`state` 为 `open`、`released` 或 `refunded`，`amount` 为争议金额，`slaId`、`evaluationSeq`、`result` 取自被争议结算。携带任意查询参数返回 `400`/`invalid_request`（先于争议查询）；争议标识非法或不存在返回 `404`/`not_found`。
- `GET /v1/disputes/{id}/events`：分页读取争议生命周期事件。查询参数仅允许且每项限单值 `limit`、`cursor`，格式、缺省值（`limit` 缺省 `50`、范围 `1..100`）与先验校验次序均沿用 SLA 评估查询：缺项、未知/重复参数、格式或范围非法在争议查询之前返回 `400`/`invalid_request`。无 `cursor` 时，`cut` 取同一读事务起点的全库最大争议事件序号（空库为 `0`）；按序号升序返回该争议内 `0<eventSeq<=cut` 的事件，续页在同一 `cut` 下再限 `eventSeq>lastSeq`。`cut` 大于当前全库最大序号、或 `lastSeq` 锚点在该争议内且不大于 `cut` 却不存在，均为 `400`/`invalid_request`（这些状态校验在争议查询之后）；争议非法或不存在为 `404`/`not_found`。成功为 `200`，正文键序 `events,nextCursor`；`events` 为对象数组，元素键序 `eventSeq,type,createdAt`，`eventSeq` 为全库唯一、持久递增的正整数，`type` 为 `opened`、`released` 或 `refunded`，`createdAt` 为事务 UTC 毫秒非负整数。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定；读取期间的并发新增不影响续页（全新首页才取新 `cut`）。旧库迁移时在单事务内按 `disputes.rowid` 升序为每个既有争议补一条 `opened`（`createdAt=0`），已裁决项紧随补一条对应 `released` 或 `refunded` 结果（时间记零），不虚构旧失败，不改动既有争议、幂等数据与重放字节；迁移仅执行一次，重启后不再补写。
- `GET /v1/disputes`：按参与账户分页审计争议集合。查询参数仅允许且每项限单值 `accountId`、`state`、`limit`、`cursor`；`accountId` 必填且为 `[0-9a-f]{64}` 格式的已登记机器 id（不含 `external:clearing`），匹配争议的付款方或收款方；`state` 可省略，提供时仅接受 `open`、`released` 或 `refunded`，按快照状态收窄结果；`limit` 为无前导零十进制整数、范围 `1..100`，缺省 `50`；`cursor=cut:lastOpenedSeq`，两段均为无前导零十进制整数。缺少 `accountId`、未知/重复参数、格式或范围非法均在账户查询之前返回 `400`/`invalid_request`；格式合法但未登记的机器返回 `404`/`not_found`；合法账户未参与任何争议时返回 `200` 空页。无 `cursor` 时，`cut` 取同一读事务起点的全库最大争议事件序号（空库为 `0`）；按 `opened` 事件序号升序返回该账户参与且打开序号不大于 `cut` 的争议，每条争议的状态由 `cut` 以内最后一项生命周期事件推导（`opened` 即 `open`），不取当前状态。续页在同一 `cut` 下只读取锚点打开序号之后仍满足原账户与状态筛选的争议；`cut` 大于当前全库最大序号、或锚点不属于当前快照及筛选结果，均为 `400`/`invalid_request`（这些状态校验在账户查询之后）。成功为 `200`，正文键序 `disputes,nextCursor`；`disputes` 为对象数组，元素先沿用单笔争议详情的键序 `id,state,amount,claimantId,payerId,payeeId,settlementSeq,slaId,evaluationSeq,result`，项尾追加 `openedEventSeq,openedAt,resolvedEventSeq,resolvedAt`：`openedEventSeq` 为正整数打开事件序号，`openedAt` 为非负毫秒时间；快照仍为 `open` 时 `resolvedEventSeq` 与 `resolvedAt` 均为 `null`，否则为 `cut` 以内结果事件的序号与时间，类型同前。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末项打开序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定；新增争议及裁决产生的新事件不进入旧快照，读取期间的并发写入不影响续页（全新首页才取新 `cut`）；迁移补出的生命周期事件按原序号直接参与排序与状态推导，不重新编号。
- `POST /v1/disputes/{id}/evidence`：为 open 争议提交不可变证据元数据。请求须携带 `Idempotency-Key` 头（格式同上），JSON 请求体仅含且不得重复 `evidenceId`（`[a-z0-9-]{1,64}`）、`actorId`（`[0-9a-f]{64}`）、`observedAt`（非布尔整数 `0..2147483647999`，UTC Unix 毫秒）、`digest`（`[0-9a-f]{64}`）。仅被争议结算的付款方或收款方可提交。判定顺序为头、体、幂等记录、争议、参与方、状态、唯一性：头、查询参数或体非法返回 `400`/`invalid_request`；同键异路径或异正文返回 `409`/`conflict`；争议缺失或标识非法返回 `404`/`not_found`；`actorId` 非付款方或收款方返回 `403`/`forbidden`；争议已裁决返回 `409`/`already_resolved`；同一争议内 `evidenceId` 或 `digest` 已被异键占用返回 `409`/`evidence_exists`。首次成功在同一写事务内原子分配全库共享的持久化证据序号 `evidenceSeq`（取全库最大序号加一，空库为 `1`，跨争议唯一），返回 `201`，正文仅 `{"evidenceSeq":正整数}`。证据、序号与幂等结果原子持久化，失败不留记录且不推进序号；同键同请求并发或重启后重放首次状态码与响应字节；相同 `evidenceId` 或 `digest` 的异键并发至多一项成功。
- `GET /v1/disputes/{id}/evidence`：分页读取争议证据，open 与已裁决争议均可读取。查询参数仅允许且每项限单值 `limit`、`cursor`，格式、缺省值（`limit` 缺省 `50`、范围 `1..100`）、先验校验次序、`cursor=cut:lastSeq` 游标及并发快照语义均沿用 SLA 评估查询，仅将资源换为争议、全局序列换为 `evidenceSeq`：缺项、未知/重复参数、格式或范围非法在争议查询之前返回 `400`/`invalid_request`；无 `cursor` 时 `cut` 取同一读事务起点的全库最大 `evidenceSeq`（空库为 `0`）；按序号升序返回该争议内 `0<evidenceSeq<=cut` 的证据，续页在同一 `cut` 下再限 `evidenceSeq>lastSeq`；`cut` 大于当前全库最大序号、或 `lastSeq` 锚点在该争议内且不大于 `cut` 却不存在，均为 `400`/`invalid_request`（这些状态校验在争议查询之后）；争议标识非法或不存在为 `404`/`not_found`。成功为 `200`，正文键序 `evidence,nextCursor`；`evidence` 为对象数组，元素键序 `evidenceSeq,evidenceId,actorId,observedAt,digest`，`evidenceSeq` 为全库唯一、持久递增的正整数。页长不超过 `limit`；有后页时 `nextCursor` 为 `cut:末序号`，否则为 `null`。`cut` 由游标携带并跨重启稳定；读取期间的并发新增不影响续页（全新首页才取新 `cut`）。
